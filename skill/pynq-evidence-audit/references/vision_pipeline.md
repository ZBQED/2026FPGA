# 视觉、量化与多板协同工作流

## 适用与输入

适用于检测→ROI→关键点→时序分类，以及多传感器并行后汇合。输入包括板卡分工、模型和预处理SHA、形状/布局/量化契约、固定回归输入、真实结果记录、质量阈值和完整延迟目标。没有真实质量标注时只能检查数值或通路，不能宣称语义准确率。

## 双手关键点与时序识别适配示例

| 通用角色 | 视觉识别中的映射 | 必须单独检查 |
|---|---|---|
| 输入选择 | 人物检测与掌部ROI | 检测类别、anchors、输入尺寸、阈值和预处理身份；不沿用其他模型的解码配置 |
| region_a / region_b | 两只手各自的21点输出，可由两块板并行计算 | 同一原始帧、左右/角色归属、ROI逆变换、遮挡与交叉后的身份保持；不能相互复用结果 |
| context | 身体关键点分支 | 点定义、输入分辨率、坐标和可见性；低分辨率候选须重新验证质量 |
| sequence | TCN等时序分类器 | 特征顺序、左右语义、缺失点mask、分段规则、置信度与真实标签；关键点质量先验收 |
| output | 叠加骨架、类别或事件并显示 | 显示结果和该帧推理对应；输出数量不能代替语义或速度验收 |

该映射仅是适配示例，分支数量、关键点数、分类器、标签与板卡分工由目标应用定义。权重、医疗词表和特定模型不随技能分发。PC可用于部署和观察；如目标要求板端自主运行，另验证移除PC核心推理后的功能与完整性能。

## 同帧并行与结果汇合

为采集输入分配frame_id并计算source_sha256；所有派生ROI保留source_frame_id和roi_frame_id。branch标识角色，ROI内容可以不同，但同一frame_id对应的原始输入必须相同。复制`examples/pipeline_contract.json`并替换各分支模型、预处理与输出约定，生产配置去掉example_only标记。

```text
python scripts/run.py pipeline --contract pipeline_contract.json --results branch_results.csv --expected-frames <采集帧数>
```

记录列与`examples/pipeline_results.csv`一致。校验器拒绝少分支、重复结果、错帧、旧ROI、模型漂移和混合输入。全部分支通过后才进入融合；不以另一帧缓存填补缺失分支。角色对应由运行器负责，例如region_a/region_b可表示两只手、两路相机或两个传感器，工具不默认推断左右手。

## 预处理与坐标

每个分支绑定颜色顺序、输入尺寸、NCHW/NHWC、dtype、归一化、scale/zero-point、舍入、饱和和padding。数值改变只更新其对应契约，不能仅改模型文件名。

对ROI原点(x0,y0)、缩放(sx,sy)、填充(px,py)，未镜像且无旋转时：x原图=(x网络-px)/sx+x0，y原图=(y网络-py)/sy+y0。归一化关键点先按约定还原网络坐标；镜像、旋转和仿射变换必须使用完整逆变换，不能套用简式。用四角、中心、边界、非方形ROI、越界裁剪与左右交换做独立几何验证。

关键点置信度、可见性和缺失点mask应随坐标传递；不能把无效点填零后当有效观测。序列输入保留点顺序、尺度基准、采样间隔、左右语义和缺失策略。新关键点分布接旧时序分类器，必须另验分类语义。

## 浮点到整数的逐阶段验证

固定原始输入，依次保留预处理、关键算子、完整输出、解码坐标、时序特征和类别结果。对整数路径先明确累加宽度、截断/饱和/舍入、偏置缩放及通道量化；黄金参考须实现同一算术语义。使用compare工具定位首个错误坐标与首个分歧阶段，禁止通过混用反量化单位或放宽门限掩盖问题。

测试集包含全零、极值、量化边界、连续不同输入、奇数尺寸、stride/padding边界、单区域和双区域、遮挡/交叉/离开重入。合成数值测试和带标签现场质量测试分别记录。

## 优化依据

先按同帧边界测量取帧、预处理、排队、传输、核执行、后处理和显示完成。核耗时降低但系统无收益时，检查调用次数、监控频率、反复分配/拷贝、短连接和轮询。确认正确性后可评估常驻进程、缓冲复用、批量调度、双缓冲和板端解码。

理想计算下界可按MAC/(lane×频率×每周期MAC)估计；传输下界按每方向字节/计时有效带宽估计。双向链路分别核算，不能用标称千兆代替协商速率与有效吞吐。所有下界均不含停顿/调度，不是达标成绩。

资源接近上限时优先复用存储、减少搬运和融合算子；增加并行核须重新核验布线、setup/hold/pulse、DRC和完整质量。HLS资源估计不等于最终全设计占用。

## 上板与恢复

记录基线位流/驱动/ABI/模型清单，识别资源拥有者。实验只加载目标板匹配的候选，有限输入、明确超时和退出路径；恢复后核验服务、资源与黄金输出。超时不能当作零耗时成功，输出缺失不能用旧结果补齐。共享资源实验按现有授权执行，不因读取技能而自动停服务。

## 已验证效果与失效条件

同帧身份校验由离线正反例验证；资源/时序方法已用于解析真实报告；性能拆分经验来自局部驱动耗时与完整后端存在大幅差额的观察。目标项目分别核验完整视觉链、坐标映射及语义输出。原始接口记录不完整、错误填报SHA、业务分支标错或缺少显示完成证据时，需要补数据。

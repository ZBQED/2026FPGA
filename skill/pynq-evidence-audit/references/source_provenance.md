# 源码与构建产物溯源

适用场景：相同文件名对应不同位流、运行库与驱动；找回二进制后需要确定其对应源码；更换编译器或目标内核。

1. 为源码集合、生成参数、编译器、目标器件与输出分别记录SHA256。使用`run.py manifest create <源码目录> <工程外清单>`冻结输入，再用verify检查构建前后输入一致。
2. 位流记录目标器件、时钟、约束和实现报告。BIT/HWH成对绑定；跨板重新构建，不由名称判断兼容。
3. ARM库记录ABI、依赖和导出接口；内核模块另外绑定目标配置、vermagic和导入符号CRC。同名内核版本不足以证明模块兼容。
4. 源码与产物的对应关系由构建命令、退出码、输出摘要及数值检查共同建立。二进制相同只证明内容一致；接口替代实现应标明为重新实现，不能写成原源码恢复。

使用templates/source_provenance.json整理绑定；输出需在新的构建目录，避免旧产物混入。

已验证效果：同大小文件改动、缺件、多件和目录越界由现有manifest回归检出；混合整数/浮点差异由compare回归检出。该说明与模板不新增板卡兼容或构建成功结论。

失效条件：仅有哈希而无可信源记录；源码树构建后发生变化；工具链、生成配置或链接依赖缺失。遇到这些条件先补充输入，不用文件名代替身份。

提炼观察：曾出现同名库对应不同执行策略、原库与替代实现混淆、内核版本相同但符号CRC不同、重建产物与旧准入清单不一致。

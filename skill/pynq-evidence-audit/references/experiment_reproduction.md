# 实验复现工作流

适用场景：陌生团队从固定输入复核数值、重建目标工程、比较优化前后耗时，或验证多设备恢复。

先填写templates/reproduction_plan.json：输入指纹、环境、目标接口、执行命令、输出位置、通过条件和恢复入口。目标名称、板卡、设备路径与阈值均由目标工程提供。

执行顺序：文件身份核验 → 固定输入与黄金参考 → 资源/时序报告 → 有边界的目标运行 → 结果身份与恢复检查。根据任务选择相关步骤，不为离线数组比较增加板端动作。

比较耗时时固定输入、工作负载、模型与终点，只在同一计时域计算间隔。多板每个分支核对帧号、输入和模型，再进行结果汇合。公布最快耗时应同时保留它对应的帧或调用记录及选择规则，不将最快值写成平均表现。

结果填写templates/reproduction_result.md。原始记录保存在工程工作区；发布日志节选需保留原记录内容指纹和节选位置。测试通过结果与可迁移的接口条件分别表述。

已验证效果：现有11步离线示例覆盖身份、数值、报告、耗时、分支汇合与清单；预期反例能被拒绝。该流程不替代目标板构建、业务准确率或其他团队复用检查。

失效条件：缺少黄金参考；输入或工作负载变化；跨设备直接相减时钟；显示终点不明确；共享资源被其他任务占用；恢复配置不属于当前启动会话。

提炼观察：分支分别成功却不能证明同帧汇合；局部核耗时不能覆盖传输和显示；旧恢复快照在重启后失效；日志批次混用会使统计失去对应关系。

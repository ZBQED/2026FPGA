# 音频输入、特征一致性和模型扩类核验

适用于PYNQ上的声学事件、语音意图、设备状态等音频项目。使用者提供目标板原理图、采集API、预处理和模型；本技能不自带麦克风驱动、训练器或业务词表，也不自动打开设备。只进行文件比较时，无需板卡。

填写 [audio_contract.json](../templates/audio_contract.json)。null是契约输入占位符，使用时填写目标参数。本流程不要求执行视觉分支。

## 1. 从可观察信号定位输入问题

先查现有应用/服务/PID是否持有音频设备或Overlay。若任务只是查看状态，用collect只读采样，不在Notebook另建BaseOverlay。确需主动实验时，在已授权范围内安排音频资源互斥、实验时长和恢复动作；记录服务原状态，避免实验与自启进程争用。

记录端口、外设类型、接线、Codec输入选择和增益的值。根据目标板的原理图与驱动核对，不从HP+MIC等文字推断所有板卡电路都相同。TRS/TRRS仅说明触点结构；偏置、引脚用途、CTIA/OMTP和外设内部接法仍需查证。换某款耳麦成功只证明该组合，不证明其他独立麦克风必然失败。

分层观察：已知兼容信号是否进入采样、目标输入是否产生与说话/敲击时刻相关的波形、是否持续零值/固定值/只有噪声、是否削顶。模拟电信号经Codec ADC变为数字采样；保存WAV只是为采样添加格式头，不是识别前必需的中间步骤。线上可以直接处理内存PCM。

## 2. 先明确PCM，再比较特征

记录采样率、有效位宽、存储dtype、字节序、声道、通道排列与满量程缩放。某些驱动用32位容器保存较低有效位宽，必须按驱动解释符号位和对齐。播放能听清有助于功能判断，但不能代替数值契约。

固定一份不含隐私的输入，保留内容SHA。PC与板端都处理这份相同的PCM，分别导出以下中间数组，按顺序使用compare定位首个分歧：

1. 通道选择/混合和幅度缩放后的波形。
2. 重采样及固定窗口处理后的波形。
3. 分帧、窗函数和频谱。
4. Mel滤波、对数和归一化后的模型输入。
5. 模型原始输出及标签解析结果。

```text
python scripts/run.py compare reference_feature.npy board_feature.npy --atol <约定绝对容限> --rtol <约定相对容限> --output feature_check.json
```

容限由算法精度、实现和量化规则确定。Log-Mel需要明确帧长/帧移、FFT、窗函数、center/padding、谱幅值或功率、Mel刻度/归一化、频带、log底数、floor和归一化参数。不能仅凭“都是Log-Mel”推断输入相同。不要在现场测试录音上重新估计训练归一化参数来制造一致。

整数和浮点混合输出可用精确有理数路径检查；大数组应考虑运行成本。工具不自动反量化、重排声道或选择另一组单位。

## 3. 增加类别时核验完整契约

分别绑定模型、预处理、归一化和标签映射的版本/内容指纹。保留基线，检查类别数、输出维度、label顺序和业务ID是否一一对应。按钮号、模型下标、线上业务ID是不同概念。

按说话人/录音来源和泛化目标划分训练、验证、测试；同一录音切片或增强版本不能分散到互相独立的集合。扩类后分别报告旧类、新类及未知/拒识样本；新增类别验证通过不等于旧类没有退化。若只验证固定说话人、固定短句，应限定结论，不能写成任意语音理解。

拒识类别使用配置中的显式集合或明确语义映射，不能从“下标大于某旧阈值”推断。分数是排序值还是校准概率也需要明确。

固定输入上的PC/PS数值一致说明移植路径一致，不等于现场麦克风、距离或噪声条件下的任务准确率。现场测量应独立保留真实输入、预期标签和输出。

## 4. 自动触发与分类分别验收

先定义触发单位和条件：RMS/dBFS等计算方式、块长、连续块数、前置缓存、采集窗口、结束方式和冷却。阈值取决于采样缩放、输入增益、麦克风距离和环境，没有所有板卡通用的门限。

分别测量：

- 安静/旁人说话/设备噪声条件：观测时长、误触发次数。
- 有效目标语音：总次数、触发次数、漏触发和截断情况。
- 已采到的有效窗口：各类别的分类结果和拒识情况。

增加带标签的计数后才计算相应比率。一次“安静时没有输出”不能推断零误触发；有音量而无意图也可能是轮次授权、触发条件或业务状态阻止推理/发送，需要检查各阶段状态。

## 5. 资源、通信与复用边界

按明确PID和窗口分别记录待机、预处理、推理、通信状态。CPU单核/整机口径与RSS共享页语义见workflow。历史模型的数据不能改名当成扩类后的测量。

模型结果与接收端播放分开验收。应用自行提供协议、ID版本、消息去重、时效、会话/轮次授权及失败策略；本技能不默认TCP/UDP、固定地址或某个接收板。通信任务只校验相关契约，不擅自移除应用已有的授权条件。

若使用latency工具，只有采集/结果/呈现三个事件在同一可信计时域，才可将一段语音窗口视作一个frame_id记录。字段中的frame可以代表逻辑事件，不要求摄像头；没有显示完成事件时，不用发送完成时间代替，而应单独报告采集至识别的时延。跨主机单调时钟不得直接相减。

当前已验证的是通用比较、资源采样及相关软件工具；本文件是从真实音频排错和扩类观察提炼的方法。它没有在所有麦克风、所有PYNQ板卡或所有音频模型上验证，模板填写完整也不会自动获得通过结论。
